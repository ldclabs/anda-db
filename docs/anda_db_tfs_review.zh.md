### 复审跟进修正

- 简单负向操作数直接从评分 map 中剔除倒排 ID。像 `common AND NOT absent1 ...` 这样的链式查询不再针对每个子句复制并全量扫描候选集。
- 混合极性候选表达式应用与顶级 NOT 相同的补集限制。前导 NOT 成对抵消，保留大结果集上的高效双重否定查询。
- 原子文件替换在遇到 `AlreadyExists` 时使用新序号重试，覆盖 PID 复用容器中的崩溃遗留文件。
- 纯元数据外壳对象在报告实时原子搜索计数的同时，保留持久化的文档统计信息。

以上跟进修正已在下方基准表格生成后完成验证。在相同开发机上针对新增 `not_many_absent` 基准进行的专项运行显示，处理 64 个缺失负向子句时，1,000 个文档耗时约 130 µs，10,000 个文档耗时约 865 µs；这接近计算初始公共倒排表的分数成本，而非执行 64 次全量候选集扫描。

## 性能与代码精简

- O01：固定语料索引与多语言分词器基准现已覆盖检索、插入、移除、清除 (purge)、flush、加载、压缩、延迟分位数及写入吞吐。独立进程模式可脱离虚拟对象存储保留上传，直接测量内存峰值。
- O02：每个新词项只放置一次。为当前词项推进满载尾部，而非再次移动所有后续词项。
- O03：查询上下文仅采样一次语料统计，缓存 IDF，预先计算长度归一化因子，并优先处理高选择性 AND 操作数。NOT 过滤器仅计算成员资格。稠密重叠的多词项评分复用首次观察到的文档长度，以增加单次查询 map 为代价减少分片查找；单词项评分不分配该缓存。算术评分前释放 map 读锁。
- O04：Flush 保留 dirty ID/版本与元数据，每次序列化并上传单个桶。在 manifest 提交前不将任何桶标为 clean。
- O05：批量 purge 使用哈希集合维护倒排表成员，并优先探测桶与 ID 交集中较小的一侧。维护性扫描保持单遍遍历倒排表。
- O06：重复出现的词项复用已有词频 map 的 key。内置 Jieba 分词链每次缓冲并排序一个 SimpleTokenizer 跨度。公开的通用归并过滤器保留 API 及全局排序语义；验证完整分词流的一致性。
- C01：变更、查询执行、持久化、压缩及测试拆分为独立的私有模块。共享的下架逻辑防止 remove 与 purge 之间产生逻辑分歧。
- C02：移除未使用的 `anda_db_utils` 依赖，修正版本号、Vec 内部表示、字节长度过滤、并发与装箱 (bin-packing) 文档说明。

## 存储架构取舍评估（O04、O05、O07）

**高频词项倒排表 (O07)：完成评估；本变更未启用分段。** 在 10,000 篇文档共享词汇表的场景下，尽管设置了 8 KiB 的放置目标，新增一篇文档仍会重写约 580 KB。这证实了文档中记录的软限制与写入放大权衡。仅在内存中做有界 flush 缓冲无法消除该现象。

跨持久化对象对单个词项进行分段会改变现有的“单拥有者倒排表/桶”不变量、加载器对账、删除记账、清单可达性以及废弃对象回收。未来的分段格式应显式对传输表示进行版本控制，支持读取现有全量倒排表，维护逐段的成员资格与脏状态，并支持原子检查点/迁移。其验收测试需覆盖段边界插入/移除/清除、部分/取消写入、缺失段、旧版本迁移以及压缩/重载一致性。应在真实存储后端上对比增量上传字节数与 p95 flush 延迟。本次变更保留现有存储格式，不隐式引入不可控迁移。

**有界并行上传 (O04)：完成评估，未引入默认 API。** 实测后端为内存接收器，数据无法体现上传延迟收益。顺序流式写入提供了内存上限保证，无需改变回调顺序或引入运行时依赖。未来可配置的并发上传器应在具有真实网络延迟的后端上评估，并确保所有上传成功后才提交清单。

**文档反向索引 (O05)：完成评估，未采纳。** 批量哈希集合优化已降低了清除成本。持久化或重新构建的“文档→词项/桶”映射会增加内存消耗，并为每个变更/加载路径增添额外不变量；仅在单文档删除成为典型业务瓶颈时才应采纳。无文本恢复应保持全量扫描，避免依赖其本身可能正在修复的记账状态。

## 复审跟进 — 2026-09-23

本轮以 `cdc5880` 为实现基线，保持 CBOR 格式不变，修复以下常见查询与维护问题：

- 对整个可结合的 OR 表达式进行归一化，包括混有 AND/NOT 的表达式。
  直接词项操作数在分词后统一去重，`run OR run OR (beta AND gamma)` 与
  `(run OR run) OR (beta AND gamma)` 的分数和排名一致；复杂分支仍贡献自己的分数。
- 压缩时为桶 ID 预留固定的最大 u32 CBOR 宽度，让旧编号不再影响装箱权重。
  在无数据修改时重复压缩不会增加版本或上传对象，重新加载后亦然；测试覆盖
  24/256 个桶的编码宽度边界。
- 空候选集在读取倒排表或估计选择性前短路，同时保留解析错误和成功查询计数语义。
- 按实际命中数分配结果 map。未命中和稀有词不再预留一千个条目，高频词查询也减少了
  结果 map 的反复扩容。继续复用统一评分路径，保留全局 DF 和历史重复倒排项的最后一项优先语义。
- 删除在获取变更门和文档条带锁之前分词。删除、purge、加载共用倒排清理与大小记账，
  删除和 purge 共用空列表原子移除及归属复查，减少嵌套 map 和临时集合，保留锁顺序与恢复语义。
- 压缩时回收闲置倒排容量，单桶索引同样适用。容量超过 64 条记录且占用不足四分之一的列表
  收缩后保留两倍存活长度的空间；仅回收容量不会标脏。
- 修正中英文文档的 flush 并发契约和条带锁顺序说明。

新增回归覆盖混合 OR 的排名及词干去重、压缩/flush/重载后的空操作压缩、持有倒排锁时的
空候选查询、在真正变更临界区暂停的删除，以及分配预算。操作模型增加 purge 和压缩；
独立的递归布尔模型校验命中集合及使用全局评分的候选子集。基准增加未命中、0/1/100
候选集、混合 OR、无变更压缩，以及删除 90% 文档后的维护。
